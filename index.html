ROUTIX FEATURES

طبقة حماية مبنية حول طلبات موقعك

مجموعة من آليات الحماية الموجودة في طبقة الـWAF مع لوحة مراقبة وتنبيهات مباشرة.

◈

Rate Limiting

التحكم في عدد الطلبات لكل IP ضمن فترة زمنية مع حماية إضافية ضد الارتفاعات المفاجئة.

⚡

Burst Protection

اكتشاف الارتفاع السريع في الطلبات والتعامل معه قبل أن يسبب ضغطًا غير طبيعي على التطبيق.

◉

SQL Injection Detection

فحص أنماط معروفة مرتبطة بمحاولات SQL Injection داخل الطلبات.

⌁

XSS Detection

اكتشاف مجموعة من الأنماط المعروفة المرتبطة بمحاولات XSS.

⌗

Risk Scoring

حساب نقاط المخاطر لكل IP واستخدامها للمساعدة في تحديد الإجراء المناسب.

⊘

Blacklist

الاحتفاظ بالمصادر التي تجاوزت سياسات الحماية ضمن قائمة حظر مؤقتة.

↯

Concurrency Control

تحديد الاتصالات المتزامنة لكل IP وعلى مستوى الخدمة لتقليل ضغط الاتصالات.

◌

Live Alerts

استقبال التنبيهات مباشرة باستخدام Server-Sent Events بدون تحديث الصفحة.

▣

Security Headers

استخدام Helmet وإعدادات HTTP إضافية لتحسين طبقة أمان التطبيق.

API & INTEGRATION

اربط Routix بموقعك

اجعل Routix نقطة الدخول العامة للموقع، واجعل التطبيق الأصلي خلف طبقة الحماية.

1
شغّل موقعك الأصلي مثال: التطبيق الأصلي يعمل داخليًا على 127.0.0.1:3000.
2
حدد TARGET_URL ضع عنوان الموقع الأصلي داخل متغير البيئة TARGET_URL.
3
وجّه الدومين إلى Routix الدومين العام يجب أن يصل إلى WAF وليس مباشرة إلى التطبيق الأصلي.
4
استخدم API Key واجهة حالة الـWAF تستخدم x-waf-api-key. 
# .env

PORT=8080

TARGET_URL=http://127.0.0.1:3000

WAF_API_KEY=ضع_مفتاحاً_عشوائياً_طويلاً

ADMIN_USER=admin

ADMIN_PASSWORD=ضع_كلمة_مرور_قوية_وطويلة

TRUST_PROXY=false

DATA_FILE=waf-db.json

RATE_LIMIT_WINDOW=60
RATE_LIMIT_MAX=120

BURST_WINDOW_MS=1000
BURST_MAX=15

GLOBAL_RATE_WINDOW_MS=1000
GLOBAL_RATE_MAX=2000

MAX_CONCURRENT_PER_IP=30
MAX_GLOBAL_CONCURRENT=1000
⚠️ لا تضع WAF_API_KEY أو ADMIN_PASSWORD داخل JavaScript الخاص بالواجهة. هذه البيانات يجب أن تبقى في بيئة السيرفر.

SETTINGS

إعدادات الحماية

إعدادات Routix التشغيلية يتم التحكم بها من متغيرات البيئة الموجودة على السيرفر.

⚙

Traffic Control

RATE_LIMIT_MAX و BURST_MAX و GLOBAL_RATE_MAX للتحكم في الترافيك.

◇

Risk Engine

RISK_BLOCK_THRESHOLD و RISK_HONEYPOT_THRESHOLD و RISK_TTL.

◷

Timeouts

REQUEST_TIMEOUT_MS و HEADERS_TIMEOUT_MS و PROXY_TIMEOUT_MS.

ABOUT ROUTIX

مطورون شغوفون بالأمن والبنية التحتية

Routix مشروع تقني طوره مطورون شغوفون بالأمن السيبراني والبنية التحتية وتطوير الأنظمة. نؤمن أن أدوات الحماية يجب أن تكون عملية، واضحة، وقابلة للمراقبة.

هدفنا بناء طبقة حماية سهلة الدمج مع المواقع والتطبيقات، وتمنح المطور رؤية أفضل لما يحدث على مستوى الطلبات والترافيك.
